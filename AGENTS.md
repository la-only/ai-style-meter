- Всё сразу: `make check`

## Жёсткие правила

1. Работа только в ветках `task/TASK-NNN-*`. В `main` — никогда. Ветку задачу создаем от `develop`.
2. `git push` — только по явной команде человека.
3. Перед коммитом `make check` должен быть зелёным.
4. TDD обязателен на двух уровнях: критерии приёмки и проверки фиксируются до кода (уровень задачи), каждый шаг исполнения — red-green-refactor (уровень исполнения). Тесты должны падать без реализации; реализация без подтверждённого red state не принимается.
5. Ни одна задача не выходит из `draft`, пока не заполнен «Круг постановщика» (уточняющие вопросы и ответы, границы, нецели, критерии приёмки) и спека не прошла чеклист самопроверки — юнит-тесты спеки. Неоднозначность помечается маркером `[NEEDS CLARIFICATION]`, а не догадывается.
6. Не выходи за `_Boundary` из task-файла. Нашёл проблему вне границ — запиши в раздел «Замечания» отчёта, не чини.
7. Публичные API, схемы данных и миграции не менять без явного пункта в спеке.
8. Не додумывай: если спека противоречива или неполна — остановись и выпиши вопросы.

## Процесс (spec-driven)

- Изменения продукта: `docs/specs/` (шаблон — `paradigm/docs/specs/PROPOSAL-TEMPLATE.md`, дельта-спеки ADDED/MODIFIED/REMOVED)
- Задачи: `docs/tasks/TASK-NNN-*.md` (шаблон — `paradigm/docs/tasks/TASK-TEMPLATE.md`)
- Архитектурные решения: `docs/adr/` (шаблон — `paradigm/docs/adr/ADR-TEMPLATE.md`)
- Отчёты ревью: `docs/reviews/`

## Definition of Done

- [ ] «Круг постановщика» в task-файле заполнен полностью (вопросы/ответы, границы, нецели, критерии)
- [ ] Чеклист «Проверка спеки» пройден, маркеров `[NEEDS CLARIFICATION]` не осталось
- [ ] Прогноз постановщика заполнен (сложность, токены, время)
- [ ] Каждый критерий приёмки из task-файла покрыт тестом
- [ ] Тесты написаны до реализации и падали без неё (red state в отчёте)
- [ ] `make check` зелёный
- [ ] В task-файле заполнен «Отчёт об исполнении», включая отступления от спеки
- [ ] Журнал прогонов заполнен по всем ролям (постановщик / исполнитель / ревьюер): время, токены, модель и источник по каждому прогону; итого по ролям; план/факт с причиной отклонения
