## Контекст

Целевая система (издательская фабрика) требует роли стилистического редактора: корректировка произвольного текста на манер конкретного автора. Скелет-прототип стилометра существует (внешний файл `Стилометр — скелет эксперимента.py`, источник идей, не кодовая база). Без измеримого паспорта стиля и дискриминатора «свой/чужой» любой контур переписывания неотличим от магии промптов: качество переноса должно доказываться метриками на отложенных данных до построения генеративного контура.

## Цель

Создать машинно валидируемый фундамент стилопереноса: стилометрический паспорт автора, скорер близости текста к паспорту и контрольный эксперимент с заранее зафиксированными порогами на паблик-домен корпусах.

### 2. Границы

- Входит: модуль стилометрии (признаки, паспорт, скорер), экспериментальный прогон (дискриминатор, дрейф, стилометрическое разделение), golden-набор маскированных отрывков, отчёт по порогам.
- Не входит: LangGraph-оркестрация, генеративный rewriter, LLM-judge, файнтюн, UI.

### 3. Нецели

- Доказательство качества переписывания как такового: задача доказывает измеримость стиля, а не качество генерации.
- Юридический аудит корпусов: используются только тексты в общественном достоянии.

### 4. Критерии приёмки (EARS)

1. WHEN строится паспорт, THE SYSTEM SHALL выдавать style.json со всеми признаками FEATURE_NAMES, без NaN/inf, с числом чанков ≥ 100 на автора.
2. WHEN вычисляется расстояние до паспорта, THE SYSTEM SHALL z-нормировать признаки по mean/std паспорта и возвращать среднее |z|.
3. WHEN завершается experiment, THE SYSTEM SHALL отчитывать AUC дискриминатора (char n-gram 3–5, LogReg) на отложенных файлах автора против чужого корпуса; порог AUC ≥ 0.90.
4. WHEN сравниваются стилометрические расстояния, THE SYSTEM SHALL применять Mann-Whitney (alternative=less) между отложенными чанками автора и чужим корпусом; порог p < 0.01.
5. WHEN считается дрейф, THE SYSTEM SHALL сохранять в JSON среднее расстояние каждого файла автора к его паспорту.
6. WHEN отрывок входит в golden-набор маскирования, THE SYSTEM SHALL исключать содержащий его файл из обучения дискриминатора и построения паспорта.
7. WHEN golden-отрывок не имеет review metadata человека, THE SYSTEM SHALL исключать его из отчётных метрик.
8. WHEN меняется любой порог после baseline, THE SYSTEM SHALL требовать новой версии отчёта и запрета подгонки по held_out.
